حالة أرشيف مَخزَن
=================
آخر تحديث: 2026-10-24
STATUS_CODE: NOT_UPLOADED

الوضع الفعلي الآن
-----------------
الملف الأصلي بصيغة 7Z وحجمه التقريبي 7 GiB لم يُرفع فعليًا إلى GitHub حتى هذا التاريخ.
لا يوجد Release حقيقي أو مجلد uploads/large يحتوي هذا الملف، ولم تُرفع أجزاؤه. الاختبارات استخدمت GitHub وهميًا ومحاكاة فقط؛ لا تعتبرها دليلًا على وجود الملف.
اسم الملف الأصلي لم يُزوّد للمشروع، والملف نفسه غير موجود في مساحة العمل.

ما تفعله الصفحة تلقائيًا عند اختيار الملف
----------------------------------------
1. التقسيم يتم في المتصفح أثناء الرفع باستخدام Blob.slice، وليس بعد تخزين الملف كاملًا.
2. إذا كانت قناة Releases متاحة، يُقسّم ملف 7 GiB إلى 4 أجزاء بحجم أقصى 1.75 GiB ويُنشأ Release مسودة.
3. إذا كانت Releases محجوبة، تتحول الصفحة تلقائيًا إلى القناة البديلة دون تدخل المستخدم:
   - تُرفع الأجزاء عبر Contents API المتاح إلى uploads/large/.
   - يُقسّم ملف 7 GiB إلى 76 جزءًا، وحجم الجزء الأقصى 95 MiB.
   - تُنشأ manifest.json بعد اكتمال الأجزاء لتعريف الملف الأصلي وترتيبها.
4. عند التنزيل يدمج الخادم الأجزاء بالترتيب ليصل ملف 7Z واحد.
5. لكل عملية ملف حالة نصي داخل uploads/status/ يوضح الأجزاء المكتملة والمتبقية.

قناة الشبكة في بيئة المعاينة
----------------------------
uploads.github.com محجوب في بيئة المعاينة، لذلك ستختار الصفحة القناة البديلة داخل المستودع تلقائيًا.
لا تعتبر وجود هذا العائق السابق سببًا لتوقف الرفع الآن؛ القناة البديلة أضيفت لتعمل عبر api.github.com المتاح.

تعليمات لمن يعمل على المشروع لاحقًا
------------------------------------
- لا تفترض أن ملف 7Z الكبير موجود على GitHub اعتمادًا على وجود الكود أو الاختبارات.
- افحص Releases وuploads/large/ وuploads/status/ للتحقق من الحالة الفعلية قبل إخبار المستخدم بأن الملف محفوظ.
- لا تعتبر الأرشيف جاهزًا إلا إذا كان STATUS_CODE: COMPLETE وmanifest.json موجودًا للقناة البديلة، أو Release منشورًا مكتمل الأجزاء للقناة الأولى.
- حالات IN_PROGRESS وINCOMPLETE وCANCELLED وDELETED لا تمثل أرشيفًا أصليًا جاهزًا للاستخدام.
