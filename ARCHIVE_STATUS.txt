حالة أرشيف مَخزَن
=================
آخر تحديث: 2026-10-24
STATUS_CODE: NOT_UPLOADED

الوضع الفعلي الآن
-----------------
الملف الأصلي بصيغة 7Z وحجمه التقريبي 7 GiB لم يُرفع فعليًا إلى GitHub حتى هذا التاريخ.
لا يوجد Release حقيقي يحتوي هذا الملف، ولم تُرفع أجزاؤه. الاختبارات السابقة استخدمت GitHub وهميًا ومحاكاة فقط؛ لا تعتبرها دليلًا على وجود الملف.
اسم الملف الأصلي لم يُزوّد للمشروع، والملف نفسه غير موجود في مساحة العمل.

ما تم تجهيزه في الكود
---------------------
1. التقسيم يتم في المتصفح أثناء الرفع باستخدام Blob.slice، وليس بعد تخزين الملف كاملًا.
2. ملف 7 GiB يُقسّم إلى 4 أجزاء، وحجم الجزء الأقصى 1.75 GiB.
3. تنشأ مسودة GitHub Release أولًا، ولا تُنشر إلا بعد وصول جميع الأجزاء.
4. عند التنزيل يدمج الخادم الأجزاء بالترتيب ليصل ملف 7Z واحد.
5. لكل عملية رفع مجزأة ملف حالة نصي داخل uploads/status/ يوضح الأجزاء المكتملة والمتبقية.

العائق الحالي
-------------
بيئة المعاينة الحالية تحجب uploads.github.com، لذلك لا يمكن إتمام رفع Release حقيقي منها.
التشغيل الفعلي يحتاج خادمًا يسمح بالاتصال بـ uploads.github.com ومضيفي تنزيل Release assets.

تعليمات لمن يعمل على المشروع لاحقًا
------------------------------------
- لا تفترض أن ملف 7Z الكبير موجود على GitHub اعتمادًا على وجود الكود أو الاختبارات.
- افحص Releases وuploads/ للتحقق من الحالة الفعلية قبل إخبار المستخدم بأن الملف محفوظ.
- عند قراءة ملف حالة في uploads/status/، لا تعتبر الأرشيف جاهزًا إلا إذا كان STATUS_CODE: COMPLETE.
- إذا كانت الحالة IN_PROGRESS أو INCOMPLETE أو CANCELLED فالأجزاء ليست أرشيفًا مكتملًا قابلًا للاستخدام.
