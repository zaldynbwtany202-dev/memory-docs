# مَخزَن — أرشيف ZIP و7Z على GitHub

صفحة عربية تحفظ الملفات المضغوطة في GitHub وتنزّلها لاحقًا. التقسيم والرفع والدمج تتم من الصفحة دون خطوات يدوية، ولا يُحمّل الملف الكامل في ذاكرة الخادم.

## المزايا

- قبول ZIP و7Z بالسحب والإفلات أو الاختيار من الجهاز.
- التحقق من الامتداد وتوقيع الأرشيف ومطابقتهما.
- تخزين الملفات حتى 100 MiB في `uploads/`.
- تقسيم الملفات الأكبر أثناء الرفع باستخدام `Blob.slice()`.
- استخدام **GitHub Releases** عند توفر قناته: ملف 7 GiB يصبح 4 أجزاء، كل جزء حتى 1.75 GiB.
- التحول تلقائيًا عند حظر Releases إلى `uploads/large/` عبر Contents API: ملف 7 GiB يصبح 448 جزءًا، كل جزء حتى 16 MiB لتجنب مهلات فحص GitHub.
- إنشاء `manifest.json` للأرشيف المجزأ بعد اكتماله، ودمج الأجزاء تلقائيًا عند التنزيل.
- ملف حالة نصي لكل عملية في `uploads/status/` يوضح ما وصل وما تبقّى، ولا يصبح `COMPLETE` إلا بعد الاكتمال.
- استئناف الرفع تلقائيًا بعد إعادة تشغيل الخادم: تُستعاد الجلسة من الحالة والأجزاء الموجودة، ولا تُرفع الأجزاء السابقة مجددًا.
- إعادة محاولة الجزء تلقائيًا حتى 3 مرات عند مهلات الفحص وأخطاء 408 و429 و5xx والشبكة، مع منع تكرار جزء وصل فعلًا.
- زر إلغاء يحذف الأجزاء غير المكتملة، وحذف الأرشيف المجزأ لاحقًا في commit واحد.
- إبقاء رمز GitHub في الخادم وعدم إرساله إلى المتصفح.
- ملف `ARCHIVE_STATUS.txt` يوضح الوضع الفعلي ويمنع افتراض أن الملف الأصلي مرفوع بالفعل.

## التشغيل

يتطلب **Node.js 20 أو أحدث**.

```bash
npm install
cp .env.example .env
```

عدّل `.env`:

```dotenv
GITHUB_OWNER=your-username
GITHUB_REPO=your-private-repository
GITHUB_BRANCH=main
GITHUB_TOKEN=your-fine-grained-token
MAX_FILE_SIZE_GB=20
```

ثم شغّل التطبيق:

```bash
npm start
```

وافتح `http://localhost:3000`.

> يمكن استخدام `GITHUB_REPOSITORY=owner/repository` بدلًا من `GITHUB_OWNER` و`GITHUB_REPO`، ويمكن تمرير الرمز عبر `GH_TOKEN` بدلًا من كتابته في `.env`.

## صلاحية GitHub المطلوبة

يُفضّل إنشاء **مستودع خاص مخصص للأرشيف** واستخدام Fine-grained personal access token:

1. اختر المستودع المستهدف فقط في **Repository access**.
2. ضمن **Repository permissions → Contents** اختر **Read and write**.
3. ضع الرمز في بيئة الخادم أو `.env` المحلي. ملف `.env` مستبعد من Git.

## كيف يعمل ملف 7 جيغا؟

1. يقرأ المتصفح توقيع الملف فقط ويطلب خطة رفع.
2. تختار الصفحة القناة تلقائيًا:
   - **Releases أولًا** إذا كان `uploads.github.com` متاحًا.
   - **أجزاء المستودع تلقائيًا** إذا كان محجوبًا؛ لا تتوقف العملية ولا يحتاج المستخدم إلى اختيار شيء.
3. ينشئ الخادم `uploads/status/<archive-id>.txt` بحالة `IN_PROGRESS`.
4. يرسل المتصفح جزءًا واحدًا في كل مرة دون قراءة الملف الكامل في الذاكرة، ثم يحدّث الخادم عدد الأجزاء التي وصلت والمتبقية.
5. في قناة المستودع، تُحفظ الأجزاء في `uploads/large/<archive-id>/` وبعد اكتمالها تُنشأ `manifest.json`.
6. في قناة Releases، تبقى المسودة غير منشورة حتى وصول جميع الأجزاء.
7. تصبح الحالة `COMPLETE` فقط بعد اكتمال التخزين، ويظهر الملف كعنصر واحد في الأرشيف.
8. عند التنزيل، يقرأ الخادم الأجزاء بالترتيب ويرسلها كملف `.7z` واحد.

## الشبكة والنشر

- القناة البديلة تحتاج فقط إلى `api.github.com`، ولذلك تعمل في بيئة المعاينة الحالية رغم حظر `uploads.github.com`.
- قناة Releases تحتاج أيضًا إلى `uploads.github.com` للرفع ومضيفي أصول التنزيل التي يحوّل إليهم GitHub.
- Releases هي الخيار الأفضل للملفات الضخمة المتكررة لأنها لا تضخّم سجل Git. قناة المستودع موجودة لضمان عمل الصفحة عند حظر Releases، لكنها تنشئ أجزاء وcommits أكثر.
- عند النشر خلف reverse proxy، اسمح بحجم الجزء المناسب: 16 MiB للقناة البديلة أو 1.75 GiB لقناة Releases، وامنح الطلبات مهلات كافية.

## الحدود والتخزين

- الحد الافتراضي للملف الأصلي **20 GiB** ويمكن تغييره عبر `MAX_FILE_SIZE_GB` حتى 100 GiB.
- الملفات حتى 100 MiB تُحفظ بصيغة:
  `uploads/<timestamp>-<unique-id>-<original-name>.<zip|7z>`
- ملفات الحالة في `uploads/status/` صغيرة ولا تظهر كأرشيف قابل للتنزيل.
- `IN_PROGRESS` و`INCOMPLETE` و`CANCELLED` و`DELETED` لا تعني وجود أرشيف أصلي صالح. الجاهز فقط `COMPLETE`.
- جلسات الرفع في ذاكرة الخادم؛ إعادة تشغيله أثناء الرفع تتطلب بدء العملية مجددًا، لكن ملف الحالة يبقى لتوضيح ما حدث.
- عند نشر الصفحة للعموم، ضعها خلف تسجيل دخول أو شبكة خاصة.
